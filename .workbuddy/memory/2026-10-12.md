### BaseFragment 设计要点
- 综合可见性 `computeVisible()`：组合 `isViewPrepared && !isHidden && isResumed && userVisibleHint`，并递归父 Fragment 可见性（嵌套 Fragment 支持）。
- 覆盖四种场景的判定来源：旧 ViewPager 用 `setUserVisibleHint`；ViewPager2 用 `onResume/onPause`（setMaxLifecycle）；hide/show 用 `onHiddenChanged`；replace/前后台用 `onResume/onPause`。
- 去重分发 `dispatchVisibility()`：基于 `isCurrentVisible` 状态位，仅在变化时回调，避免重复。
- 三个钩子：`onFirstVisible()`（首次可见仅一次，View 销毁重建后重置）、`onVisible()`（每次可见，含回到前台）、`onInvisible()`。
- `onDestroyView` 重置 `isFirstVisible/hasLoadedOnce` 与 `isCurrentVisible`。
- 兼容性：仅用 API 1 即可的方法，`minSdk=23` 无影响；`setUserVisibleHint` 标 `@Suppress("DEPRECATION")` 仅供旧 ViewPager 兼容。

### BaseActivity 设计要点
- `switchFragment(containerId, fragment, tag)`：多 Fragment 同容器切换，隐藏其余、show/add 目标，懒加载友好。
- 事务统一 `commitAllowingStateLoss()`，避免 onSaveInstanceState 后崩溃（代价：极端进程回收可能丢事务，UI 切换可接受）。

## TitleBar 标题居中修复（左右不等宽导致标题偏位）
- 现象：`centerContainer` 用 `weight=1/0dp`，仅占「左栏结束→右栏开始」剩余空间，其几何中心 = `(leftW + barW - rightW)/2`，左右不等宽时偏离整条 bar 中点 `barW/2`，标题看着偏左/偏右。
- 修复：在 `TitleBar.onLayout` 中 `super` 之后调用 `recenterTitle()`，对 `titleWrapper` 做 `translationX` 修正：期望中心 = 整条 bar 中点 `barW/2`，并用 `[leftW + targetW/2, (barW-rightW) - targetW/2]` 钳制防压到左右内容（空间不足时退化为区域居中）。
- 关键点：`titleWrapper.left` 是相对 `centerContainer` 的坐标，`centerContainer.left == leftW`（无 padding），故绝对中心 = `leftW + target.left + targetW/2`；`translationX` 不影响 `getLeft()`，故 onLayout 内计算幂等、无反馈环。
- `titleWrapper` 为 GONE（即 `setCenterView` 插入自定义 View）时跳过修正。左右/标题的可见性或文本变更会通过 `setVisibility/setText/addView` 自动触发 relayout，从而自动重新居中。

## TitleBar 标题居中重构：translationX → centerContainer 不对称外边距（用户优化要求）
- 原 `recenterTitle()` 给 `titleWrapper` 做 `translationX`，且只在 `titleWrapper.VISIBLE` 时执行（`setCenterView` 插入自定义 View 时不生效）。
- 新方案：不改子 View，给 `centerContainer`（FrameLayout, weight=1）设**不对称外边距**使其在整条 TitleBar 居中。
  - 水平 LinearLayout(weight=1) 下 centerContainer 中心 = `(barW + L + mL - R - mR)/2`，令其 = `barW/2` 需 `mL - mR = R - L`。
  - 等价实现：`diff = R - L`；`diff>=0`（右更宽）→ `leftMargin = diff, rightMargin = 0`；`diff<0`（左更宽）→ `leftMargin = 0, rightMargin = -diff`。该式等价于「取 max(L,R) 作基准、左/右各留 `max-L`/`max-R` 边距」，即用户说的「取 max + 对应外边距」。
  - 子 View（titleWrapper 或 setCenterView 自定义 View）由 `layout_gravity/gravity` 在 centerContainer 内自动居中，无需平移。
- `recenterTitle()` 不再 early-return（与 titleWrapper 是否显示无关），`setCenterView` 的自定义 View 也受益；用 `lp` 变更前后比对做 guard，避免 onLayout 内重设 layoutParams 引发无限 relayout。
- 同步将 `setCenterView` 的自定义 View LayoutParams 由 `MATCH_PARENT×MATCH_PARENT` 改为 `WRAP_CONTENT×MATCH_PARENT` + `gravity=CENTER_HORIZONTAL`，与 titleWrapper 居中行为一致（如需铺满宽度可自行改回 MATCH_PARENT）。

## TitleBar 居中修复补强：计入左右栏 margin（+ TitleBar 自身 padding）
- 用户指出 `recenterTitle()` 中 `vb.leftContainer.width` / `vb.rightContainer.width` 不含 margin，导致左右栏带外边距时计算偏离。
- 修复：用 `ViewGroup.MarginLayoutParams` 取出左右栏的 `leftMargin/rightMargin`，实际占据宽度 = `width + leftMargin + rightMargin`，重算 `diff`。
- 公式升级：`mL_c - mR_c = (rightOcc - leftOcc) + (pR - pL)`（pR/pL 为 TitleBar 自身左右 padding，无 padding 时为 0；保证相对「整条 TitleBar」居中而非仅内容区）。
- cast 由 `LinearLayout.LayoutParams` 改为更通用的 `ViewGroup.MarginLayoutParams`；布局类型不变（仍为 LinearLayout.LayoutParams 运行时实例），重设 layoutParams 安全。

## TitleBar 沉浸式高度修复：内容区不被状态栏 padding 挤压
- 问题：原 `applyStatusBarPadding()` 只给 TitleBar 设 `paddingTop=状态栏高度`；若用户给 TitleBar 设了固定 `layout_height`（如 base 布局曾用 50dp）或 `minHeight`，内容区 = 总高 - paddingTop 会被吃掉，标题被挤扁。用户不知道状态栏高度，不会主动加。
- 设计：把「内容高度」与「状态栏高度」解耦。
  - init 中先 `contentHeight = dp2px(48)`（默认 48dp），再 `readAttrs`（可经 `tb_height` 覆盖），最后 `applyStatusBarPadding()`。
  - `applyStatusBarPadding()` 改为：设 `statusBarHeight` 字段 → 调 `updateHeightForInsets(top)`；并在 `OnApplyWindowInsetsListener` 中按真实 insets 同步更新。
  - `updateHeightForInsets(top)`：`updatePadding(top=top)`（背景延伸到状态栏）+ `minimumHeight = contentHeight + top`（保证内容区 >= 内容高度）。
  - 新增 `onMeasure` 兜底：若用户写死 `layout_height`（EXACTLY 模式忽略 minHeight），`measuredHeight - paddingTop - paddingBottom < contentHeight` 时 `setMeasuredDimension(measuredWidth, contentHeight + paddingTop + paddingBottom)` 把总高补足。
- 新增 attr `tb_height`（dimension，默认 48dp），XML 配置内容高度；无对应运行时方法（属布局属性）。
- base 布局 `fragment_base.xml`/`activity_base.xml`：移除 `android:minHeight="?attr/actionBarSize"`，`layout_height` 改 `wrap_content`，改由组件内部管理高度（内容高度 + 状态栏）。`fragment_base.xml` 原 `layout_height=50dp` 正是此 bug 的复现点。
- 注意：`onMeasure` 内 `setMeasuredDimension` 后不会重测子 View；因 `gravity=CENTER_VERTICAL`，额外高度居中分配，内容不被压扁。
