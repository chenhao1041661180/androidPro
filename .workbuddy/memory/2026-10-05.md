# 2026-10-05

## AndroidPro 网络框架调整
- `core/network/NetworkClient.service()` 增加泛型缓存：新增 `private val serviceCache = ConcurrentHashMap<KClass<*>, Any>()`，用 `computeIfAbsent` 保证每个接口仅 `retrofit.create` 一次；`service()` 签名加 `: Any` 上界；`initialize()` 内 `serviceCache.clear()` 以在重入时让旧 service 失效。
- 原因：避免多处重复调用 `service<T>()` 时反复创建代理实例（JVM/Retrofit 已缓存 Class 与方法解析，但获取点分散不优雅）。
- 现状：`service()` 当前未被实际使用，home feature 走 `SimpleHttp` 路径（`PostRepository` 中调用被注释）。Retrofit 版本 3.0.0，接口方法须为 suspend，不支持返回 `Call<T>`。
- service 实例无状态、线程安全，可安全缓存为单例。

## service() 兼容性修正（API 23）
- 项目 minSdk=23（app 与 core:network 均 23），未开启 core library desugaring → `ConcurrentHashMap.computeIfAbsent` 在 API 23 设备 NoSuchMethodError 崩溃（ART 自 API 24 才换 OpenJDK 8 实现的 ConcurrentHashMap）。
- 已将 `service()` 改为双重检查锁定：仅用 get/put/synchronized（Android API 1+ 全版本兼容），逻辑等价、零重复创建。
- 修正编辑时误入的 `private` 修饰符，确保 service() 对外可见。
- 备选：开启 core library desugaring 亦可保留 computeIfAbsent，但代码层规避更稳、不依赖构建配置。
